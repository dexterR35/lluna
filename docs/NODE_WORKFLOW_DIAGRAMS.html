How images, masks, previews, and parent flows work.

Each node owns its model, settings, latest artifact, and preview. Typed wires move images, masks, prompts, and video forward. Parent flow boxes organize complete start-to-end scenarios without mixing their settings.

SupportedBackground + protect mask

Connect an image and an optional mask to Remove Background. Masked pixels are forced to remain opaque.

SupportedGenerate and preview

Generate Image stores its artifact on the node. Preview Image can show the same result downstream.

PartialMasked regeneration

LaMa can fill an edit mask now. Prompt-guided inpainting needs a dedicated Image + Mask + Prompt node.

Protect mask behavior

A Protect Mask does not tell the model what to remove. It overrides the final alpha only where protection is painted.

White / brightPreserve these pixels.
Black / darkAllow normal removal.

Two ways to create it

  1. Load Mask: drag a prepared grayscale mask into a Load Mask node.
  2. Select Object: connect the same source image, name or click the object, then connect its MASK output.

Execution rules

What happens when you press Run

The graph is validated first, then executed in dependency order. Completed artifacts remain attached to their nodes for previews and saving.

Node run iconRuns from that node through every connected downstream result.
Parent run iconRuns the box’s recorded start nodes through its complete end state.
Multiple parentsKeep them independent. Run any box without changing another box’s models or settings.
GPU-heavy workLocal inference is serialized. Avoid launching several heavy runs simultaneously or one may report Busy.
Preview persistenceLatest artifacts are saved on nodes and restored when the workflow reopens.
No bypassEvery enabled node in the selected execution path runs. There is no bypass logic.
No cyclesEditing is a forward chain. Add another processing node instead of wiring backward.
Typed connectionsIMAGE connects to IMAGE, MASK to MASK, PROMPT to PROMPT, and VIDEO to VIDEO.
